1. 核心结论

技术判断

前沿模型开始被安全审查和区域访问限制影响。手机厂商不能把关键 AI 功能绑定在单一海外 API 上，需要"模型可替换 + 数据可控"的双供应链。

架构影响

AI Phone 的核心从"接一个聊天模型"转向"端侧模型 + 云端模型 + 本地知识库 + 系统权限"的组合架构。壁垒在端云调度与 NPU 能效，不在聊天入口。

本周风险

Agent 能调用工具后误操作风险明显变大；PLM、BOM、服务器、项目资料不能直接开放写权限。强模型不一定能全球稳定可用。

本周机会

端侧 RAG 和 PCB-QA 等研究把 AI 从概念带到工程评测；GLM-5.2 等开放权重模型提升内网自部署吸引力，适合架构部做小范围试点。

一句话：我们不追"哪个模型最强"，而是跟踪 AI 技术怎么变、对手机架构意味着什么、哪些方向值得试点。

3. 五大技术趋势判断

从近两周新闻中提炼的可跟踪方向，供架构部持续观察。

1前沿模型进入受控发布

GPT-5.6、Mythos/Fable 均因安全审查先小范围开放。模型能力≠全球可用性。手机厂商需建立多供应商、多区域、可降级策略。

观察信号：各厂商 API 开放范围、区域限制政策、红队评测要求。

2开源/开放模型成为企业第二供应链

GLM-5.2 等开放权重模型提升内网自部署吸引力。适合涉密文档、日志分析、规范 RAG 等数据不出域场景。

观察信号：开放模型 benchmark、量化版本、NPU 移植进展。

3Agent 从聊天走向执行

Fugu 多 Agent、AI Coding Agent 表明 AI 正从"回答问题"转向"调用工具完成任务"。权限、日志、回滚和人工确认成为刚需。

观察信号：Agent 事故案例、企业治理框架、MCP 生态成熟度。

4端侧 AI 从体验卖点变成架构能力

端侧 RAG on NPU 论文验证能效优势。AI Phone 壁垒在端云调度、NPU 算子覆盖、隐私权限，而非预装聊天 App。

观察信号：Qualcomm/MediaTek NPU SDK、1B/3B 端侧模型、弱网降级方案。

5AI 开始进入硬件研发流程

PCB-QA、GenAI for PCB 综述、Wireless Foundation Model 表明 LLM 正进入 EDA/CAE/通信研发。短期价值在审查和摘要，不在自动闭环设计。

观察信号：PCB 审图问答准确率、3GPP RAG 效果、仿真脚本自动化成熟度。

5. 端侧 AI 与 AI Phone 架构影响

NPU / APU

关注算子覆盖、prefill/decode、embedding、rerank、ASR、视觉 encoder 的功耗曲线。多 Agent 并发需任务调度能力。

内存与存储

1B/3B/7B 模型量化、KV Cache、向量索引、模型按需加载。中低端机 RAM 预算是硬约束。

端侧 RAG

适合个人知识库、相册问答、设备说明书、离线客服；核心是隐私和弱网。NPU 能效是关键指标。

端云协同

端侧做隐私和低延迟，云端做复杂推理；弱网时自动降级。需定义切换阈值。

功耗与热

Agent 是连续负载，不是短峰值；要测 10 分钟对话、检索、摘要场景下的温升和续航影响。

系统权限

AI 调相机、文件、日历、通讯录时，必须任务级授权和可撤销，纳入 OS 安全审计。

用户场景

翻译、相册问答、设备自诊断、学习助手、售后客服。

系统权限层

文件、相机、日历、通讯录、位置等任务级授权。

端侧小模型

低延迟、隐私、弱网可用；承担识别、摘要、初筛。

本地 RAG

检索说明书、用户资料、历史记录，再交给模型回答。

云端大模型

复杂推理、多步 Agent、跨语言高质量生成。

安全审计

来源追溯、操作日志、敏感动作确认、可撤销。

架构判断：AI Phone 不是"预装一个聊天 App"，而是 OS 权限、端侧算力、云端模型、本地知识和审计机制的组合。壁垒在端云调度与 NPU 能效。

6. 传音重点市场机会

传音不能只看云端大模型——弱网、多语言、低成本、端侧推理是差异化关键。

市场特征用户痛点优先 AI 场景架构要求技术动态关联
非洲 / 南亚弱网 网络不稳定、流量贵 离线翻译、网页摘要、低流量搜索 端侧模型 + 缓存 + 弱网降级 端侧 RAG on NPU；GLM 等本地备选模型
多语言环境 英语、法语、阿语、本地语言混用 通话/会议摘要、多语种输入、学习助手 端云 ASR + 小模型摘要 + 语言包管理 多模型供应链；端云协同架构
中低端机占比高 RAM、存储、功耗预算有限 轻量助手、图片/文本初筛、设备自诊断 1B/3B 小模型、int4/int8 量化、按需加载 小模型趋势；NPU 算子覆盖
售后服务分散 用户不会描述故障、服务成本高 设备自诊断、维修知识库问答、故障日志摘要 本地日志摘要 + 云端知识库 + 人工转接 多 Agent 诊断流程；端侧 RAG
传音策略：优先投入端侧推理能力和弱网降级，而非追逐最新云端大模型。模型可替换、数据可控是底线。

8. 架构部 AI 能力成熟度评分表

用于部门自评：不是评价个人，而是判断各岗位 AI 能力是否已经从“会用”进入“可复用流程”。

等级能力状态典型表现下一步行动
0没用过只听过 AI 新闻，不知道能解决什么工程问题。完成一次公开资料调研，要求附来源链接。
1会问答能让模型解释概念、总结公开资料，但结果依赖个人经验。建立岗位常用提示词，要求答案带出处。
2会做资料摘要能摘要 PD、测试报告、规范片段、竞品资料。沉淀摘要模板，统一输出字段和检查项。
3能跑 Skill / 固定流程能用固定流程生成表格、报告、审查清单，结果可复核。把高频任务做成部门 Skill，至少跑通 3 个历史案例。
4接入内部资料能基于文档库、问题单、测试库做 RAG 问答，答案可追溯。建设只读 MCP / RAG，做权限分级和日志记录。
5形成稳定流程AI 输出进入评审、试验、复盘闭环，并有量化指标。持续度量节省工时、准确率、返工率和风险事件。

短期目标

一个月内让六个岗位至少达到 3 级：能跑固定 Skill / 固定流程。

平台目标

工具负责人推进 4 级试点：只读知识库、规范 RAG、问题单 RAG。

风险边界

达到 5 级前，不允许 AI 自动写 PLM、自动改 CAD/PCB、自动给最终设计结论。
